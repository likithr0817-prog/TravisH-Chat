# Make JABBI AI feel "unlimited"

True unlimited tokens doesn't exist — every model has a fixed context window, and every request costs credits through the AI Gateway. But we can get very close to unlimited *feel* on the three technical fronts, and I'll be straight with you about billing.

## 1. Unlimited conversation length (auto-summarization + sliding window)

Right now every message in a thread is resent to the model on every turn, so long threads eventually hit the context window and also burn credits fast.

- Before each send, count approx tokens in the message history.
- If under a safe budget (e.g. 60k tokens), send as-is.
- If over, keep the last ~20 messages verbatim and replace everything older with a running "Conversation summary so far: …" system note.
- The summary is generated by a cheap model (`google/gemini-3.6-flash`) in the same request pipeline and cached on the conversation row (new `summary` + `summary_up_to_message_id` columns) so we only re-summarize new tail messages, not the whole thread each time.
- Result: threads can grow to hundreds of messages without ever erroring on context length.

## 2. Longer single responses (raise output + auto-continue)

- Set `maxOutputTokens` on `streamText` to the model's max (e.g. 8192 for Gemini Flash, higher for Pro).
- Detect when a response ended because of `finish_reason: "length"` (not natural stop).
- Automatically issue a hidden "continue" follow-up call and stitch the streamed text onto the same assistant message in the UI, up to a configurable cap (default 3 continuations) so a runaway model can't drain credits.

## 3. Bigger inputs / file uploads (chunk + pre-summarize)

Current file upload inlines the whole file text into the message, which blows up context on anything large.

- On upload, if the extracted text is over ~15k tokens, chunk it and run a fast summarization pass server-side before it enters the conversation.
- Store both the summary (sent to the model) and the original text (kept in the message parts for the user to re-open), so the user still sees "attached: report.pdf" but the model sees a compact summary + the chunks most relevant to the current question.
- Bump the client-side upload cap from 2 MB to 10 MB for text-like files.

## 4. Billing — the honest part

You can't have unlimited usage for free on the Lovable AI Gateway; every call costs credits and the gateway hard-rejects with 402 when the workspace runs out. Two real paths:

- **Stay on Lovable AI Gateway**: add credits or upgrade the plan in Settings → Plans & credits. Everything above still helps because summarization + sliding window meaningfully cuts credits-per-turn on long threads.
- **Bring your own key (BYOK)**: I can add a per-user OpenAI/Gemini API key setting. When present, the server routes that user's requests through their own key instead of the Lovable Gateway, so their usage is billed by OpenAI/Google directly and doesn't touch workspace credits at all. This is the closest thing to "unlimited" — you pay the provider directly at their per-token rate.

Say the word if you want BYOK included and I'll fold it into step 4; otherwise I'll ship steps 1–3 and leave billing as-is.
